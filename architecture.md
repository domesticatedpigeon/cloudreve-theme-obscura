# Architecture

## React and Redux access
- React fiber: from root[__reactContainer$].stateNode.current.
- Redux store: found via props on the root's children.
- Per-element fiber: el[__reactFiber$…]. Component state is reached by walking hooks (e.g. the viewer slider hook holding onScale/scale; its queue.dispatch sets {overlay}).
- API calls: use window.crApi(path, params) (defined right after crT; GET /api/v4/<path>, resolves to the JSON body). Never read access_token from cloudreve_session directly: it expires after access_token_ttl (1h) and Cloudreve only refreshes it lazily, inside its own requests, so a page left idle sent a stale token (401) and recent thumbnails stopped loading. crApi mirrors SessionManager.getAccessToken: a token within 10 minutes of access_expires is refreshed via POST /session/token/refresh (one shared in-flight request) and kept in memory, and the newer of that and the stored token is used. Refresh tokens are stateless JWTs, so refreshing alongside Cloudreve is safe (it refreshes in parallel itself). Signed out or refresh token expired: no Authorization header.

## Layout modes
- html.cr-dock: desktop layout (the header becomes the dock nav). Set by dock(), which runs every second and on mutations/resize, only when innerWidth >= 600.
- html:not(.cr-dock) inside @media (max-width: 599.95px): mobile layout.
- Shared pill classes:
	- .cr-lp: generic 44px pill (icon-only pills get width 44, no padding).
	- .cr-tbp-mc: mobile header pill (frosted, 1px border, 3px side margins).
	- .cr-tbp-av: header avatar pill (44px pill, 32px avatar, transparent).
	- .cr-tbp-m: mobile button-group holder.
- The avatar button must never get .cr-tbp-mc. Cloudreve renders a Skeleton before the avatar loads, and React doesn't reset className when the child swaps, so a tag added during the skeleton sticks (wide frosted ring, 3px shift). The tagger skips buttons containing .MuiAvatar-root or .MuiSkeleton-root and strips .cr-tbp-mc from them.
- Avatar IconButton (UserAction.tsx) changes size when the session loads, so its className can be rewritten; class taggers re-run on an interval.

## Lazy chunk failures
- Cloudreve's Vite build lazy-loads viewers (e.g. Artplayer with its CSS). If a chunk's stylesheet fails to load, Vite throws and the app shows its error page. The footer listens for vite:preloadError: a CSS failure is suppressed (preventDefault, so the module still loads) and the stylesheet is re-added with a cache-busting query (up to 3 tries); a JS chunk failure (usually a new deployment) reloads the page once per 15s window (sessionStorage guard).

## Boot gate
- html.cr-boot hides #root until styling is applied; html.cr-booted marks the reveal.
- It must not freeze Cloudreve's .fade-enter/.fade-exit transitions.
- A safety net force-finishes stuck fades.

## Image viewer
- A fork of react-photo-view (.PhotoView-Portal).
- The Lightbox's MUI Backdrop is the portal container, but it is null on the first render, so the portal starts in body and moves on re-render or close. Closing rebuilds the portal as a new DOM node. Any script touching the portal must handle both locations.
- My custom chrome lives outside it, in the body:
	- Top pills: .cr-vtop (filename, resolution/size, ICC profile pill .cr-vinfo-s)
	- Dock: .cr-vdock (.cr-vdock-g groups, .cr-vround round pills, background picker .cr-vbgpick/.cr-vbgpop, silhouette .cr-vsilp). The silhouette slot (.cr-vsilwrap) stays reserved (44px) when empty only in the centered mobile row (.cr-m); in the right-aligned dock it is hidden when empty so the last pill lines up with the top-right Download pill.
	- Thumbnail strip: .cr-vstrip (mobile)
	- Cursor peek thumbnail: .cr-vpeek (desktop/mouse only, built in the strip script, reuses its thumbnail loader; wraps first↔last; sits opposite the cursor)
	- Custom cursor: html.cr-cur-* classes (hand/grab, prev/next) set by the legend script for the whole portal, including outside the image; the system cursor returns only over buttons and viewer chrome (its SKIP list).
	- Wrapping (first↔last) always goes through the footer's wrapGo (toast + entrance animation) for keyboard, wheel/trackpad, touch swipes and the edge arrows: the slider's loop prop is forced to false, because react-photo-view otherwise loops natively (plain slide) when there are more than 3 images. Wraps skip Cloudreve's loadMorePlaceholder (paginated folders): first→last goes to the last loaded image, and the last loaded image moves on to the placeholder (loads more) instead of wrapping.
	- loop: false and maskClosable: false are set as PhotoSlider.defaultProps (React 18 applies them when Lightbox creates each element), not only by mutating the current props object: every index change re-renders PhotoSlider with fresh props, and for that render loop was back on with more than 3 images, which changed every PhotoBox key (remounting all three boxes twice per step). The props mutation remains for the element created before the defaults existed.
	- portalContainer: Lightbox's Backdrop ref is null on its first render, so the portal starts in body and only moved to the Backdrop on Lightbox's next render, the first navigation, recreating the boxes then (no slide, a blink). The override sets portalContainer to the Backdrop (found through Lightbox's ref hook) right after opening.
	- react-photo-view zooms a PhotoBox in from scale 0.01 when its image loads within 250ms of the box mounting (its open animation). Only boxes present in the first 600ms after the viewer opens keep it; boxes mounted later get data-cr-nozoom for 800ms, which disables transitions on the box and photo, so a new image never scales in. Wraps animate only through wrapGo.
- Clicking outside the image hides/shows the interface like clicking the image: a script forces the slider's maskClosable prop to false (react-photo-view's mask tap closes only when it's true, else toggles overlay). Cloudreve's re-renders bring back a fresh props object, so it re-applies on mutation and pointerdown, then forces a slider re-render through its state hook so the tap handler picks up the new value. Don't block mask taps (an older script nudged PhotoBox's CX on mousedown to cancel them).
	- Hint legend: .cr-legend
	- Edge glow: .cr-vedges
- Background palette: System (default, follows OS) plus fixed swatches; html.cr-vlight drives light styling for viewer menus and dialogs.
- Pills fade via the registered @property --cr-fo, not opacity, so backdrop-filter keeps working (plain opacity makes them flash transparent).
- Close animation: 180ms fade of image, backdrop and pills. .cr-vghost re-inserts a copy of the old portal while React rebuilds it; [data-cr-tf] + --cr-tf freeze the photo box transform so it doesn't jump to matrix(0.01…).
- ICC profile: parsed from PNG iCCP (DecompressionStream deflate), JPEG APP2 ICC_PROFILE and WebP ICCP; name from desc/mluc tags; cached in profCache. Shown only when not sRGB.
- While the interface is hidden (portal .PhotoView-Slider__clean, html.cr-h46), the toolbars (BannerWrap, .cr-vtop, .cr-vdock, .cr-vstrip, .cr-legend) and their children get pointer-events: none, so the area keeps the custom cursor and a click there reaches the slider, which toggles the interface back (maskClosable is off).
- Viewer pills use the global pill palette (light: rgba(240,240,240,.72) with a rgba(0,0,0,.08) border, the same as --cr-tbp-bg/--cr-tbp-br; dark already matched). Both the CSS tokens and the paint script's PAL must change together. Placement matches the file toolbar: desktop pills 10px from the top and bottom and 20px from the sides; on phones the top row sits 6px from the top (like the header pills), the bottom dock sits like the bottom nav (20px sides, --cr-fab-gap from the bottom), and the thumbnail strip 8px above it.

## iOS Safari / Liquid Glass
- WebKit samples fixed layers at the screen edges to tint the status and address bars, and clips fixed content at the bars.
- The area under the status bar shows the html background unless document content exists there. The lift script (touch only, LIFT = 200) extends the viewer portal 200px past both edges so it renders under the bars; it handles the portal in body or in the backdrop and restores on close.
- Avoid edge-touching animated layers (e.g. the old left/right cue) on mobile: they retint the bars.
- Mobile native zoom: .cr-zs/.cr-zc overlay with mirror and scroll modes. Double-tap zooms in/out with an elastic bounce; touchstart is redirected to the holder's onTouchStart so pinches outside the image still work; taps outside the image don't close the viewer; a synthetic resize refits on rotation.
- Chrome can't reproduce Liquid Glass issues. Use Chrome only when the user allows it.

## Navigation drawer
- Not resizable. Cloudreve's SplitHandle (a fixed 8px Box with cursor: ew-resize, sibling of the drawer) is disabled by scanning stylesheets for pure .css-* rules with a resize cursor and setting pointer-events: none/opacity: 0 on them under #root (DataGrid column separators don't match). A stored custom width is reset to 240 (globalState/setDrawerWidth).

## Pinned folders
- Support drag sorting.
- Order saved in localStorage key cr-pin-order:<userId>.
- Custom folder colour/emoji is cached before the sidebar first opens, so reopening doesn't refetch.

## Recent files
- Cloudreve doesn't track views, so the footer records them: a store subscription watches globalState slices named *Viewer/*Player/*Editor (not viewerSelector, the "Open with" picker) and, when one opens with a file, puts it first in localStorage. The image viewer only stores the file it opened with, so a 300ms poll also reads the slider's images[index].file and records each image the user moves to.
- Keys: logged in, one list cr-recent:<userId> holds My Files and share-link files, so both roots show the same items; anonymous share visitors get cr-recent:s:<shareId>. Stored share paths keep the password; comparisons strip it. Up to 30 stored, 12 shown.
- The .cr-recent row (label + horizontally scrolling .cr-recent-i cards) is inserted before the first grid section of .cr-explorer, only in grid view and only at the My Files root or a share link's root (decided from the URL's path param, not fileManager.path, which only updates once the new listing loads). The label copies the section label's className so it matches "Folders"/"Files".
- Cards mirror Cloudreve's grid file tiles (GridFile.tsx): square, background --cr-ft-bg computed like GridFile.tsx from Cloudreve's MUI theme (light: palette.grey[100], dark: palette.grey[900]; icon panel: palette.background.default). The theme is read from the ThemeProvider props above a grid tile's fiber; since that fiber can be the stale alternate, the palette whose mode matches the system color scheme is used. Don't sample tile colors from the DOM: selection, hover and the 250ms background transition make live samples wrong; live sampling (skipping hovered/selected tiles) is only a fallback when no theme is found, 48px header with the file type icon (24px, 16px/12px margins) and 12px/500 name, then a thumbnail area inset 8px with 8px radius; thumbnails are contained and centered (video thumbnails cover the whole area instead, as do video tiles in the grid: .cr-vid, set when siteConfig icons map the extension to the video icon, else a default video extension list; the global img[draggable=false] contain !important rule has to be outranked), and files without one show a 64px (48px mobile) icon on background.default (--cr-ft-ic). Colors are recomputed at most every 500ms, when the row is inserted, and after a light/dark switch. Icons follow siteConfig.explorer.typed.icons like FileTypeIcon.tsx: extension = name.split(".").pop() lowercased (as Cloudreve's fileExtension), precedence icon > img > iconify; built-in icon paths are copied from Cloudreve's Icons/*.tsx and @mui/icons-material Android (FICONS, must cover every key of Cloudreve's builtInIcons), custom img icons are <img>, iconify icons are loaded like @iconify/react: its localStorage cache (iconify<N> keys) first, else the JSON API on api.iconify.design, api.simplesvg.com, api.unisvg.com in order; the SVG is built from the icon body and used as a data: URL mask (the span stays hidden until it loads, else it is a solid square). color/color_dark via --cr-fic/--cr-fic-d. The row rebuilds whenever the icons object changes identity (config reload), not only when it first appears.
- Navigation: the row lives inside Cloudreve's .fade-* explorer box. Leaving the root, it stays while that box is .fade-exit (so it fades out with the page) and is removed the frame the box stops exiting, because Cloudreve reuses the same box for the next folder. If no exit starts within 250ms (in-place update) it is removed then. Entering the root, it is only inserted next to a grid that isn't exiting, so it fades in with the new box.
- Selection rectangle: .cr-recent is in the gallery script's `ignored` list and the row stops mousedown/pointerdown, so neither the custom drag-select nor Cloudreve's starts there. Never stop mouseup on the row: the drag-select ends on document mouseup.
- Clicking a card or the row's empty area (not the scroll arrows) clears the file selection (fileManagerSlice/setSelected []), like clicking empty space. The row stops click propagation, so it does this itself.
- Thumbnails: loaded like Cloudreve's loadFileThumb: the fileManager tree thumb cache if present and not expired, else crApi("file/thumb") with the file's sys:shared_redirect link if it has one (as getFileLinkedUri does), and the result is stored back with fileManagerSlice/setThumbCache, so the row and the grid share one cache. Signed URLs are not persisted in localStorage (they expire, ~1h). An img that fails to load marks its cache entry expired (setThumbCache with an empty url and a past expiry, which Cloudreve also treats as a miss) and retries. API failures log a console warning with the server code and aren't cached. Cards are built before the row is inserted and the row can be detached while React swaps the grid, so results apply whenever the img still belongs to the current row; never gate on isConnected. Files without one show their file type icon.
- Scrolling: .cr-recent-wrap holds the row and two arrow pills (.cr-lp.cr-recent-arrow, icon-only so 44px). The row masks its edges with registered --cr-rl/--cr-rr lengths (animated), switched on by .cr-fl/.cr-fr when there is hidden content on that side (updated on scroll, resize and rebuild). An arrow shows whenever that side can scroll, except on mobile (hover: none or max-width 599.95px), where arrows, their shades and the edge fade mask are removed and the row is swiped. Arrows page by whole cards to exact snap points (card offsetLeft - 20px scroll-padding): next brings the first card cut off on the right to the start; previous shows the cards just before the first fully visible one. Never scroll by an arbitrary amount: scroll-snap would then re-snap abruptly later. Arrows are vertically centered on the cards and inset 20px, so they line up with the first/last card, the + New button and the avatar.
- Clicking a card navigates to the parent folder if needed, waits until fileManager list.parent is that folder (the path updates before the list does), then sends the tile a dblclick so Cloudreve's own open logic runs. If the loaded folder doesn't contain the file, the entry is dropped.
- Context menu (right click or the reused .cr-grid-more ellipsis): fetches the full file from /api/v4/file/info, selects it and dispatches fileManagerSlice/setContextMenu with type "file" and targets {path: file}. The selection is cleared once the menu and any dialog close, if the file isn't in the current listing.

- Thumbnail retries: 1.5s, 5s, 15s, 45s, 2min, each asking the server for a fresh URL; cards still without a thumbnail retry on visibilitychange/pageshow (img.crItem holds the entry).
- Scroll snapping (x proximity) applies only to touch; on fine pointers it is off because it snapped trackpad and Magic Mouse momentum scrolls to cards.
- Edge fade: the row's mask eases over 96px (smoothstep-like stops at 25/50/75%: 0.16, 0.5, 0.84) and animates in over 0.45s.
- Insertion timing: Cloudreve's explorer fade wrapper swaps the new list in while still .fade-exit and only then flips its class to .fade-enter, without any childList mutation. sync() therefore also runs on fade-* class changes, so the row is inserted in the same frame the new list starts fading in (otherwise it popped in later and pushed the folders down).

## Safe areas (landscape iPhone)
- The footer adds viewport-fit=cover, so in landscape the page reaches under the Dynamic Island (left/right safe-area insets) and uses the desktop dock layout (width >= 600). In html.cr-dock the docked drawer spacer (.MuiDrawer-docked, content-box) gets padding-left: env(safe-area-inset-left) and its fixed paper is moved right by the same amount (so the inset is reserved whether the drawer is open or closed), and main gets padding-right: env(safe-area-inset-right). Insets are 0 elsewhere, so other devices are unchanged.

## Mobile
- The + pill (.cr-new) is only shown on file browser pages (html.cr-home, set from location /home by dock()); elsewhere on mobile, e.g. Shared by me, Cloudreve's + menu only offers New remote download, so it is hidden. It is also hidden in Trash and Shared with me.
- Toolbar taps must not scroll the page (iOS Safari scrolls when MUI focuses a menu/popover in its fixed overlay). On touch devices: HTMLElement.focus defaults to preventScroll inside .MuiPopover-root/.MuiMenu-root/.MuiModal-root/.MuiDialog-root, and for 800ms after a tap on a header/toolbar button (header button, .cr-tbp-m button, .cr-tbp-mc, .cr-tbp-av) any scroll of the document or main scrollers that the user didn't start (no touchmove) is reverted to its pre-tap position.
- Bottom navigation (.cr-bnav, phones only): a nav built in body with the shared mobile pill class .cr-tbp-m and two .cr-bnav-i tabs, My Files (cloudreve://my) and Shared with me (cloudreve://shared_with_me), with Cloudreve's HomeOutlined/Home and People/PeopleFilled icons (filled when active). Shown via html.cr-bnav-on on every page when signed in; hidden during the boot gate. The bar also holds the segmented-control thumb, so tab loops go over :scope > .cr-bnav-i, never bar.children. It sits at the + pill's height (top: var(--cr-fab-top)), 20px from the left, and stretches to 6px before the + pill (the header's gap between pills); tabs grow from their content width. Below 360px wide the compact bar drops tab icons and tightens padding so both labels fit. When the + pill isn't visible (checked live: Trash, Shared with me, pages outside /home), html.cr-bnav-wide (mirrored as .cr-wide on the bar so the thumb re-measures) stretches it to 20px from both sides with equal-width tabs. A tab is selected only on /home with a matching path. The active tab gets Mui-selected, and the segmented-control script (CFG) adds the sliding, draggable .cr-tseg-thumb. The bar and + pill sit --cr-fab-gap (8px; max(8px, safe-area-inset-bottom) when installed) above the bottom. The body gets 44px + --cr-fab-gap of bottom padding (the grid adds its own 20px; the gallery gets a 20px margin) and, in list view, the virtualized item list (inner scroller) gets a ::after spacer of 64px + --cr-fab-gap, so the last item is never covered. Never add content after the explorer's children on mobile (e.g. an ::after spacer): the explorer has overflow:auto and a height from its content, so extra content makes it a nested scroller that captures the swipe and rubber-bands on iOS.
- The sidebar is a popover styled as a floating, frosted card with the pill border (no drop shadow: Liquid Glass clips it). Its frosted backdrop extends under the bars in light and dark mode.
- The + menu (Cloudreve "new" context menu) is pinned above the + pill via data-cr-fabm on its .MuiMenu-root. Use a data attribute, not a class: MUI rewrites the Modal root className on open/close (MuiModal-hidden), wiping added classes. The root is collapsed to height 0 and its backdrop stops short of both bars, so no fixed layer touches the screen edges (prevents bar tint).

- Pinned path bar (phones): the path row (main > .MuiStack-root > .cr-h72.cr-nav) is position: fixed (not sticky: on iOS a sticky row rubber-bands away from the fixed header when the page is pulled down at the top) at top: var(--cr-pb-top), full width, z-index 1090 (below the header's 1100), with the page background and 6px bottom padding (the gap between pills). Its Stack gets padding-top: var(--cr-pb-h) to keep the content in place. Both variables are measured by the cr-scrolled script (the Stack's document top and the row's height, refreshed on DOM changes) so the stuck position is exactly the resting position. The header's 1px separator moves to the row's ::after while it exists, shown with html.cr-scrolled. cr-scrolled also tracks the list view's [data-virtuoso-scroller]. In mobile list view the list box is pulled up 8px (and the virtuoso viewport padded 8px) so rows scroll right up to the separator instead of leaving an empty strip.
- Desktop scroll separator: grid and gallery keep the see-through toolbar gradient (.cr-fade) when scrolled, with no band or line. In list view a 1px var(--cr-sep) line appears under the column header row once the list scrolls. Desktop gallery content starts at 48px + 2 * --cr-nav-top so the toolbar's gap below matches its gap above, and the explorer's 12px radius is removed there.
- The path bar is navigation-only on phones: a capture-phase click listener swallows taps inside .cr-path that aren't on a button, so Cloudreve's Breadcrumb onEdit never switches to the text field (crumb buttons stop propagation themselves and still navigate). Desktop keeps click-to-edit. Hover/focus/touchstart events inside .cr-path are also stopped on phones, so a tap doesn't open the crumb's name tooltip or the share-info popover (both hover-bound); clicks still navigate.

## Spotlight
- Painters (toolbar, drawer, fades) get viewport cursor coordinates and use background-attachment: fixed. Tiles (TILES: grid cards, recent cards, list rows, gallery items, share cards) get coordinates local to each tile and a normal (scroll) attachment: fixed backgrounds inside an element with a scale/transform (the press feedback) are mispositioned in Safari, which hid the glow after selecting or deselecting. Tiles default to --cr-tx/--cr-ty: -999px so an unlit tile never inherits a painter ancestor's viewport coordinates (in Safari the properties are unregistered and inherit, which lit every card at the same local spot when hovering the sidebar). Because the coordinates are local, the light is recomputed on every scroll frame (the tile list is re-queried at most every 500ms, and immediately after any DOM change, so cards rendered after a reload light up on the next pointer move).

## Root headings
- At the My Files root (/home with no path or cloudreve://my) the Shared with me root (cloudreve://shared_with_me) and share-link roots (cloudreve://<id>[:pwd]@share, titled with the root crumb's text minus the owner avatar), html.cr-myroot is set and the path pill is replaced by an h4.cr-root-h (Cloudreve's navbar.myFiles / navbar.sharedWithMe string, swapped via dataset.k) in the docked heading style (Boldonse 24px, uppercase). The heading lives inside the path box (prepended to .cr-path); at a root the box drops its pill look and shows only the heading. Never add siblings to the toolbar row, and never rely on positional children of .cr-path (the heading is its first child: the breadcrumb box is .cr-path > .MuiBox-root:first-of-type, and the mobile autoscroll looks it up with :scope > .MuiBox-root): the pill styling of the right-hand groups uses .cr-path + .MuiBox-root chains, mobile rules use the row's :first-child and desktop spacing uses .cr-lead + * in whichever row holds it (desktop toolbar or the mobile path row) and is hidden everywhere else. Heading and path pill fade in (cr-page-in, 0.3s) whenever they swap. A heading too long for its slot shrinks its font size to fit on one line (min 12px), re-fitted on text or width changes. The heading is a block with text-box: trim-both cap alphabetic, centered in the 44px path box (flex), so its capitals center on the pills at any size regardless of the engine's Boldonse metrics.

## Tabs
- Settings tabs: Cloudreve's MUI Tabs are replaced by a built .cr-stabs strip. Its edge fades (--cr-sl/--cr-sr) are recomputed on scroll, on resize of the strip or any tab (ResizeObserver), on DOM mutations and when fonts load. Overflow is measured from the last tab's right edge, not scrollWidth, because the selection thumb (.cr-tseg-thumb) overshoots with a springy easing and would count as overflow.
- Details pane tabs (desktop side pane and the mobile fullscreen sidebar dialog) share the pill class .cr-ptabs, added by the class tagger to any .MuiTabs-root in the pane or in a .MuiDialog-paperFullScreen. All pill tab rules and the sliding thumb target .cr-ptabs.

## Viewer dialogs
- Fullscreen dialogs (mobile details pane, viewers on mobile) use --cr-bg with no MUI elevation overlay; non-fullscreen dialogs use the frosted --cr-menu-bg.
- Cloudreve's ViewerDialog (video, WOPI, PDF, etc.) is matched as .MuiDialog-paper.cr-h73 (title + divider): a 28px card with 10px padding and an 18px bordered content box.
- Title: Cloudreve renders [actions][file name][fullscreen, close]. With actions (e.g. the video viewer's subtitles button) the name is reordered to the left and the actions join the buttons on the right, so every viewer's title reads the same.
- Title insets: the file icon is inset like the close glyph (the IconButton's 8px padding): windowed title padding 10px 0 10px 8px (icon and X glyph both 19px from the paper edge), fullscreen 10px 10px 10px 18px. The archive viewer (paper :has(.MuiTable-root)) pads its content 16px inside the box, so its title is 10px 8px 10px 16px to line the glyphs up with that content.
- The video viewer dialog (.MuiDialog-root:has(.art-video-player), or .cr-vdark, which a MutationObserver adds as soon as a viewer dialog's title names a video file, before Artplayer's lazy chunk loads) always uses the dark token set, with a black content box from the first frame, (same as the image viewer side panel), so its title bar is dark in light mode too. Artplayer's loading spokes are replaced with the image viewer's arc spinner (36px white arc, 0.6s rotation, delayed fade-in).
- Video (Artplayer, box :has(> .art-video-player)): black background. Artplayer's autoHeight writes an inline height on the box and resizes .art-video-player (e.g. 44% width / 93% height for vertical videos) when metadata loads, which moved the video. The windowed box gets a fixed height (min(100vh - 160px, 900px)) and .art-video-player is forced to 100% x 100% (except in Artplayer's web fullscreen), so the video letterboxes in place and controls span the player.
- When fullscreen (always on mobile), it goes edge to edge: no radius or padding, and the content box drops its border and flexes to fill the height below the title. This overrides the video player's inline autoHeight and its calc(100vh - 350px) min-height, so Artplayer centers the video in the space instead of sitting at the top.

## Press feedback
- Recent cards and grid tiles ([data-rect-id]) scale to 0.97 while pressed (the scale property with springy easing, so it doesn't fight transforms). Pressed means :active or [data-cr-press], which the press script sets on pointerdown for any mouse/pen button (found with elementFromPoint) and clears on pointerup/pointercancel: Chromium never applies :active for the right button, so right clicks had no feedback. Touch keeps :active only.
- A contextmenu that lands outside the pressed tile (Windows fires it on mouseup, when the tile has shrunk, so an edge click missed it and opened the empty-space menu) is re-dispatched on the pressed tile.
- html.cr-scrolling (set for 140ms by any scroll or wheel event) turns off pointer events on tiles and rows so scrolling doesn't trigger hover work. Mac trackpads emit wheel events during a two-finger click and momentum, so right clicks fell through to the explorer (empty-space menu, no press). pointerdown therefore clears cr-scrolling at once, and it is not set again while a pointer is down. The contextmenu event is hit-tested again after pointerdown, so it reaches the tile.
- Select pills (.cr-lp.MuiSelect-root) don't zoom as a whole on hover (a wide pill's content visibly zoomed from the center). Instead the value text scales 1.06 from its left edge and the arrow scales in place (using the scale property so MUI's open-state rotate transform still applies).

## Avatars
- Avatar menu header (.cr-acct): the group/role line next to the username is hidden. The header is padded 1px more than the menu items (15px) so the username's ink lines up with the icon glyphs (Fluent icons have ~2px of padding inside their 20px box).
- Cloudreve colors a user avatar's background from the nickname (shown while the picture loads, or behind a letter if it fails). User avatars (img src containing /user/avatar/) and the header avatar's letter fallback use a neutral rgba(var(--cr-spot-rgb), 0.12) instead.

## Page entrance
- Pages fade in once, as a whole: the container (main div.cr-h29 > .MuiContainer-root) runs cr-page-in. On docked desktop pages (html.cr-dock-page) the container doesn't animate; its children except the first (the heading box, docked into the top bar) run cr-page-in, so the heading shows instantly like the rest of the top bar. Don't add a second, delayed animation to children such as the docked heading box (html.cr-dock-page … > .MuiBox-root:first-child) or the profile/settings sections; stacked fades made headings appear late. dock() runs synchronously on mutations for 800ms after a navigation, so cr-dock-page applies in the page's first frame and needs no fade to hide the move.

## Profile page loading
- /profile pages render in stages (heading "-", skeletons, avatar image, list). A script keeps html.cr-pf-wait (container and children at opacity 0, animation none) until there is no skeleton, the heading has real text and the avatar image is complete, capped at 1.5s per path; removing the class restarts cr-page-in, so the page fades in once.

## Settings page
- No enclosing boxes: every tab is a plain list of label/value rows (160px label column, 16px column gap, 16px row padding) separated by 1px var(--cr-sep) lines, max 760px wide.
- The Profile tab is identified by the avatar upload input (Stack :has(> .MuiGrid2-container input[type="file"])), never by .MuiAvatar-root: passkeys and linked accounts also render avatars, and matching on them treated Password and security as Profile.
- Profile: the avatar row comes first. On ≥600px it follows the row pattern ("Profile picture" in the label column, the 72px avatar and the Edit button in the value column); on phones it stacks like the other input rows: the label above, then the avatar with the Edit button beside it. On phones the settings container uses the app's 20px side gutter (MUI's 16px misaligned it with the header pills). Email and Display name and, with the two Grid2 rows flattened (display: contents), UID, Sign up date, Group and Public profile follow as rows. Sections after the profile grid (e.g. Account linking) are rows separated by the same line.
- Checkbox groups (Cloudreve's outlined box around a FormControlLabel, e.g. version retention) are borderless with the description under the label, like the Tree view row. Every table part in settings uses --cr-tbp-br for its lines.

## Copy/move dialog tree
- The folder tree (.MuiDialog-paper.cr-h41) scrolls in a Grid2 column under the absolutely positioned title. The column is pulled 10px left with 10px of padding (and a 10px right margin to keep the file pane in place) so its overflow no longer clips the tree's -10px offset, which squared off the items' left corners; it has a stable scrollbar gutter and a top mask (transparent to 30px, opaque at 54px) so items fade out under the heading. Items use the main sidebar's pill radius, and each nested [role=group] is indented 16px (the dialog's padding override had removed Cloudreve's per-level indentation).

## Text fields (.cr-tf)
- The focused border and focus wave use :has(input:focus, textarea:focus, :focus-visible), not :focus-within: the path bar is a .cr-tf that also contains breadcrumb buttons, and a mouse-focused button must not leave it looking focused.
- Selected text in .cr-tf inputs uses the accent pink (rgba(233, 138, 180, 0.35)), keeping the text color.

## File tags
- Cloudreve's FileTag adds color="error" to a chip whose tag color's contrast text differs from text.primary (a hack for the delete icon), so which tags get MuiChip-colorError depends on the light/dark palette. The status chip tint rules (colorSuccess/Error/…) therefore skip [data-cr-tag]; a script marks every chip rendered by FileTag (a fiber up to 20 levels up has a tagColor prop) once, from a childList MutationObserver. Tags keep Cloudreve's own colors (background = tag color, contrast text) in both modes.

## User setting defaults
- Tree view > Auto expand defaults to off. Cloudreve's SessionManager keeps the session (cloudreve_session) in memory from boot and falls back to its own defaults (tree_view_auto_expand: true) for unset keys, and the footer can't reach that object or run before boot (the footer is parsed before the async module runs, but they race). So the setting-defaults script (right after crApi) fills unset keys (DEFAULTS) in each session's settings and anonymousSettings: once in localStorage on load (effective from the next boot), and in every JSON.stringify of an object shaped like Cloudreve's session state, so SessionManager's own syncToStore keeps the default and fills its in-memory copy. A value the user set is never changed.

## Translations
- Use Cloudreve's own strings wherever a matching key exists. The first footer script defines window.crT:
	- crT(key, fallback): looks up "ns:path" (default ns application) for the current language (html lang, else localStorage i18nextLng, else en-US) from i18next's localStorage cache (i18next_res_<lng>-<ns>), fetching /locales/<lng>/<ns>.json if missing; trailing "..."/"…" is stripped. Returns the English fallback if there is no key.
	- crT.set(el, key, fallback, "text" | "aria" | "title"): sets the string and marks the element (data-cr-t / -ta / -tt) so it is re-translated when the language changes or a locale file finishes loading.
	- crT.is(text, key, fallback): compares against the translated or English text (for finding Cloudreve's own menu items).
	- CSS strings use variables set by the helper: content: var(--cr-t-drop, "…"), var(--cr-t-search, "…").
- Keys in use: navbar.recentlyViewed, navbar.searchFiles, navbar.setting, navbar.myFiles, navbar.sharedWithMe, fileManager.new, fileManager.moreActions, fileManager.download, fileManager.rename, fileManager.pin, fileManager.saveShortcut, fileManager.dropFileHere, fileManager.color, setting.syncWithSystem, share.copyLinkToClipboard, common:close.
- Strings with no Cloudreve equivalent stay English: viewer hint legend, viewer background/proofing names (except System/Color), Actual size / Zoom to fit, edge-wrap toasts, Expand sidebar, View options, Drag to reorder, recent row Scroll left/right, Sections.

## Scrollbars
- The explorer and page scrollers (.cr-explorer, main div:has(> .MuiContainer-root)) scroll under the docked top bar, so on desktop (html.cr-dock) their ::-webkit-scrollbar-track gets margin-top: var(--cr-sbt) (a script copies each scroller's computed padding-top into --cr-sbt) and margin-bottom: 20px, lining the scrollbar up with the content and the details pane.
- Chrome 121+ ignores ::-webkit-scrollbar styling on elements with scrollbar-color/scrollbar-width set, so in browsers supporting ::-webkit-scrollbar those two scrollers reset both to auto; Firefox keeps the standard thin scrollbar (no track margins there).

## List and gallery views
- List view (react-virtuoso): rows are [data-testid=virtuoso-item-list] > [data-index] > .MuiBox-root, the header row is the first child of the box holding [data-virtuoso-scroller]. Styled like the grid: rows inset 20px, 12px radius, no separators, hover background var(--cr-tile) and the shared spotlight (rows are in the spotlight TILES list), press scale; thumbnails get 8px radius and the tile outline; names 12px/500; header labels 12px/500 dimmed, no border.
- Mobile list: only the name column (it already shows size and date), no header row, no horizontal scrolling (the list root's min-width is reset).
- List decorations (script at the end of the footer): each row's name line (first cell > p > .MuiBox-root; on mobile the icon host has no aria-haspopup, so it is found structurally as the line's first div) gets our own .cr-lcb squircle checkbox (always visible at 0.55, pink and opaque when selected; a click forwards to Cloudreve's icon onClick so selection logic stays Cloudreve's), a .cr-lti type icon (crFicon for files, a pinned clone of Cloudreve's svg for folders) and a .cr-grid-more.cr-lmore ellipsis (always visible; dispatches contextmenu on the row). Cloudreve's own icon host is hidden in plain mode (it swaps to a checkbox on hover/selection, which looked glitchy), and in thumbnail mode the thumbnail's badge and select overlay are hidden so the type icon and checkbox sit outside the thumbnail. CSS keys off line:has(> .cr-lcb) instead of row classes, because React rewrites the row's className on selection. Cells and header cells have 6px side padding; rows reserve 40px on the right for the ellipsis.
- In list view the document must not scroll (the list scrolls internally), so the bnav body padding is skipped when the explorer holds a [data-virtuoso-scroller]; otherwise the path bar could be scrolled away.
- Gallery: .cr-gallery-name labels are hidden until the item is hovered (hover devices) or selected (checked squircle checkbox). Gallery images cover their tile with square corners (8px only while selected and inset) (overriding the early contain rule; they fill the content box, so the selected padding inset still shows).
